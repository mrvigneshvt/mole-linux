# Decision: M4.2 coredumps are report-only — 2026-10-19

The owner clarified in issue #17 revision 1 that system coredumps must not be deleted by mole-linux. The clean rule calls `coredumpctl list --no-pager --json=short` to report the count and reports the readable size of `/var/lib/systemd/coredump`; tool errors are `Unavailable`, unreadable size is `Unknown`.

The rule uses `RecoveryMode::ReportOnly` (not `OwnerNative`: owner-native items run owner commands), is never selected by default, and produces the `attention` outcome in both preview and apply runs. System retention remains owned by systemd-tmpfiles and `coredump.conf MaxUse=`.
