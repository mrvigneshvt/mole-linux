# Decision: v1 scope, license, interface — 2026-10-19

Decided by the owner in session (brainstorm after upstream research). Evidence base: [upstream review](../research/mole-upstream-review.md).

| Decision | Choice | Consequence |
|---|---|---|
| Code reuse / license | GPL-3.0; upstream Mole logic may be ported | `Cargo.toml` `license = "MIT"` must change. `GPL-3.0-only` vs `-or-later` not yet chosen. Keep attribution to tw93/Mole for ported logic. |
| Milestone 1 | Read-only storage analyzer (`mo analyze` equivalent) | No deletion, no sudo in M1. Hardlink/sparse/mount-boundary accounting and explicit partial-scan reporting are acceptance criteria. |
| Distro scope | Arch/Omarchy only for v1 | Other distros later via capability probing, not distro-name switches. |
| Interface | TUI from day one | Requires new deps (expected: ratatui + crossterm) — exact crates/versions still need explicit approval in the plan. Keep scan/model core separate from TUI so it stays unit-testable; JSON output from the same model is cheap and testable. |
| Name | Deferred; must change before public release | Upstream TRADEMARK.md asks forks not to use Mole branding. `mole-linux` is a working name only. |

Resolved 2026-10-19: toolchain rust stable 1.99.1 via mise/rustup; license `GPL-3.0-only` (orchestrator default, cheap to change); deps approved: ratatui, crossterm, rustix. Plan: [plans/M1-analyzer.md](../plans/M1-analyzer.md). Implementer: Codex gpt-6-luna medium via Superset; this session orchestrates/reviews.
